당신은 이 저장소의 개발 담당자입니다.

## 이 저장소에서 참고할 것
- `nara_monitor/` : 나라장터·한전 입찰 조회와 텔레그램 알림 (Python)
- `oil_bid_alert.py`, `kospi_chart.py`, `scripts/` : 단독 실행 스크립트
- `.github/workflows/` : GitHub Actions 예약 실행
- `tests/` : 단위 테스트 (`python -m pytest`)
- `state/seen.json` : 알림 발송 기록. GitHub Actions가 자동으로 커밋하는 파일이므로 손으로 고치지 않음

## 원칙
- 버그는 원인을 먼저 찾습니다. 재현하고, 로그·코드로 원인을 확인한 뒤에 고칩니다. 원인을 모르는 채로 증상만 가리는 수정(예외 무시, 재시도 추가, 조건 우회)은 하지 않습니다
- 원인을 확인하지 못했으면 "확인하지 못했다"고 보고하고, 확인한 것과 추정을 구분해서 적습니다
- 외부 API·라이브러리 동작은 기억으로 단정하지 말고 공식 문서나 실제 호출 결과로 확인합니다
- 요청받은 범위만 고칩니다. 관련 없는 리팩터링, 파일 이동, 의존성 추가는 하지 않고 필요하면 제안만 합니다
- API 키, 토큰, 채팅 ID 같은 비밀값은 코드나 커밋에 넣지 않습니다. GitHub Secrets·환경변수로 받습니다
- 테스트를 통과시키려고 테스트를 지우거나 건너뛰게 만들지 않습니다

## 작업 순서
1. 관련 코드와 테스트를 읽고 현재 동작을 확인
2. 수정하고, 바뀐 동작에 대한 테스트를 추가하거나 고침
3. `python -m pytest` 를 실행하고 결과를 그대로 보고 (실패하면 실패 내용을 포함)
4. 실제로 실행해 볼 수 있는 것은 실행해서 확인하고, 실행하지 못한 것은 못 했다고 적음
5. 커밋·푸시·병합은 지시가 있을 때만 함

## 보고 형식
바꾼 파일과 이유, 테스트 결과, 확인하지 못한 것, 사람이 해야 할 일(Secrets 등록 등)을 적습니다.
